# Product

## Register

product

## Platform

web

## Users

HomeOps is for generic households that want a free, understandable way to manage chores, home maintenance, errands, recurring responsibilities, durable information about the property, and eventually larger household projects. The primary users are everyday household members, including people who are not technically savvy, who need to set up a household, invite others, assign or share work, understand what needs attention, and find important home details without learning a complex productivity system first.

The product should also support a public marketing landing page that explains the value before login, then an authenticated app experience where household members do the work.

## Product Purpose

HomeOps provides a free household operating system for recurring chores, maintenance, errands, shared responsibilities, and durable property knowledge. It should help households see what needs doing, decide what is ready or blocked, keep recurring upkeep from being forgotten, coordinate work across invited members, and retain important details about home systems such as HVAC, electrical, plumbing, generators, roofs, and chimneys.

The House Binder is the household's durable reference area. HomeOps-supplied sections combine a curated set of structured fields with freeform notes. Household-created sections begin as notes-only so people can record observations and context that do not fit a predefined field.

Projects are a future premium feature: a project groups tasks toward a particular outcome, such as a lawn renovation, move, room refresh, repair effort, or contractor-heavy home improvement plan.

Success means a household can start simple, trust the app quickly, find both the work and property information it needs, and grow into more structured planning only when the household work actually needs it.

## Positioning

HomeOps gives any household a free, approachable way to manage chores, maintenance, and durable property knowledge in one clear shared operating system, with premium project planning available when work becomes outcome-driven.

## Brand Personality

Friendly, optimization-minded, and empathetic. The product should feel helpful without becoming bossy, organized without feeling corporate, and capable without asking users to think like project managers.

## Anti-references

HomeOps should not feel like an over-optimized enterprise dashboard, a technical admin console, or a power-user productivity tool that hides basic actions behind dense configuration. It should avoid UX that prizes theoretical efficiency over clarity for ordinary household members.

## Design Principles

Start understandable, then reveal power. The first experience should make the next household action obvious; advanced planning should appear when the task calls for it.

Optimize for real homes, not perfect workflows. The interface should tolerate interrupted work, changing priorities, shared responsibility, and tasks that depend on weather, money, time, or other people.

Plain language beats system language. Labels, empty states, and errors should use household words before architecture words.

Shared context reduces coordination cost. Status, due windows, blockers, ownership, and activity should help people understand why something matters and who can move it forward.

Keep knowledge in context. Durable property reference belongs in the House Binder, task-specific observations belong with the task, and future project notes belong with the project. Do not create a generic Notes destination until a distinct user need justifies one.

Free core value comes first. Premium project planning should feel like a natural extension for outcome-based efforts, not a gate around everyday household usefulness.

## Accessibility & Inclusion

Target WCAG AA. The product should use responsive layouts, keyboard-accessible workflows, visible focus states, reduced-motion support, readable contrast, and plain-language copy. Patterns should work for non-technical household members and for users coordinating work across different devices and levels of comfort with software.
